## 1. 目标

简化设置界面的动画，降低弹簧缩放、容器高度动画和折叠展开动画带来的视觉跳动、等待感和实现复杂度，同时保留必要的交互反馈、键盘操作、焦点行为和无障碍语义。

推荐目标不是让整个应用完全无动画，而是将设置界面收敛到以下行为：

```text
打开/关闭设置：短时间淡入淡出，不缩放、不弹簧、不复杂变形
切换设置分类：内容立即替换，不做容器高度动画
展开 Provider：内容立即显示/隐藏，不做 grid 高度动画
鼠标悬停和控件状态：保留必要的颜色/边框反馈
```

这样可以减少设置界面独有的动画，同时不影响其他弹窗和主界面已有的交互。

`ModalShell.tsx` 当前有三阶段生命周期：


主要动画机制：

- 首次挂载后通过两次 `requestAnimationFrame` 切换到 `open`；
- `.modal.modal--animated` 使用 `opacity + transform: scale(0.96)`；
- `.modal-overlay--animated` 使用背景色和 backdrop-filter 变化；
- 关闭时设置 `closing`，等待 transitionend 或 400ms fallback 后执行 `onClose`；
- `prefers-reduced-motion: reduce` 时直接跳过动画。

相关 CSS 位于 `src/renderer/src/App.css:956-1023` 附近。

### 2.2 设置分类切换使用动态高度动画

文件：

```text
src/renderer/src/components/SettingsModal.tsx:795-835
```

当前设置页面有四种状态：

```tsx
type SettingsPage = 'index' | 'general' | 'agent' | 'mcp'
```

分类切换时会：

1. 读取当前 `.settings-shell` 的 `offsetHeight`；
2. 保存为 `frameHeight`；

7. 等待 `transitionend` 清除固定高度。

```tsx
const shellRef = useRef<HTMLDivElement>(null)
const [frameHeight, setFrameHeight] = useState<number | null>(null)
const [resizing, setResizing] = useState(false)
const navigate = (...)
const capSettingsHeight = (...)
const onFrameTransitionEnd = (...)
```

这是当前设置界面动画实现中复杂度最高、最适合优先移除的部分。它涉及 DOM 测量、内联 height、`requestAnimationFrame`、`useLayoutEffect` 和 transitionend，多次快速切换页面时还需要处理动画状态竞争。

## 3. 推荐方案

### 3.1 动画分级策略

建议将 `ModalShell` 增加一个可选的动画模式，而不是直接修改所有弹窗的全局行为：

```ts
type ModalMotion = 'default' | 'simple' | 'none'
```

`SettingsModal` 使用：

```tsx
<ModalShell
  onClose={onClose}
  dialogClassName="settings-modal"
  labelledBy="settings-modal-title"
  motion="simple"
>
```

建议语义：

| 模式 | 适用范围 | 行为 |
|---|---|---|
| `default` | 现有普通弹窗 | 保持当前缩放、淡入和 backdrop 动画 |
| `simple` | 设置弹窗 | 只保留短淡入淡出；不缩放、不使用弹簧曲线 |
| `none` | reduced-motion 或测试 | 立即显示和关闭 |

这样可以避免设置动画简化影响密码弹窗、确认弹窗、权限弹窗和其他现有 UI。

### 3.2 设置弹窗打开/关闭：保留短淡入淡出，移除缩放

建议新增设置专用 class，例如：

```text
modal-motion-simple
```

推荐行为：

- dialog：`opacity 0 -> 1`，时长约 100–140ms；
- dialog：不再使用 `transform: scale(0.96)`；
- easing：使用普通 `ease-out` 或较简单的 `linear/ease`，不使用 spring；
- overlay：避免 backdrop-filter 从无到有的渐变；可以保持静态遮罩，或只做极短的 opacity 过渡；
- 关闭 fallback 时间同步缩短到不超过动画时长加少量余量，避免设置关闭后仍延迟销毁。

注意：不要为简化设置动画而直接改写 `.modal.modal--animated` 的全局规则，否则其他弹窗会被无意改变。

### 3.3 设置分类切换：移除动态高度动画

建议修改 `SettingsModalBody`：

1. 删除 `frameHeight` 状态；
2. 删除 `resizing` 状态；
3. 删除 `shellRef`，如果不再用于其他逻辑；
4. 删除 `capSettingsHeight`；
5. 删除 `useLayoutEffect`；
6. 删除 `onFrameTransitionEnd`；
7. 将 `navigate` 简化为：

```tsx
const navigate = (next: SettingsPage): void => {
  if (next !== page) setPage(next)
}
```

8. `.settings-shell` 保留普通布局，不设置 inline `height`；
9. 删除 `.settings-shell.is-resizing` 的 height transition 和相关 reduced-motion CSS。

新的页面切换应当是：

```text
点击分类 -> page 更新 -> 内容立即替换 -> modal 按自然内容高度布局
```

这样可以消除高度测量和 transitionend 竞态，也不会影响分类标题、返回按钮或表单状态。

### 3.4 Provider 展开/收起：改为即时渲染

推荐保留现有 `expanded` 状态和 `aria-expanded`，仅移除动画：

```tsx
<button aria-expanded={open} ...>
```

实现选项按推荐顺序：

#### 推荐：条件渲染内容

```tsx
{open ? (
  <div className="agent-provider-card-body">
    ...
  </div>
) : null}
```

优点：

- 不需要 grid-row 动画；
- 不保留隐藏内容的布局和交互风险；
- DOM 与视觉状态一致；
- 更容易测试。

#### 备选：CSS `display: none/block`

如果为了减少 JSX 改动，可以保留 collapse wrapper，但使用：

```css
.agent-provider-card-collapse {
  display: none;
}

.agent-provider-card.is-expanded .agent-provider-card-collapse {
  display: block;
}
```

同时移除：

- `grid-template-rows`；
- `transition: grid-template-rows ...`；
- chevron 的 `transition`；
- expanded 状态的 `transform: rotate(...)`。

若使用条件渲染，建议保留箭头静态图标，不再旋转；也可以用不同的静态图标表达展开/收起，但不应引入新的动画。

### 3.5 保留必要的交互反馈

动画简化不等于移除所有状态反馈。以下内容建议保留：

- 设置分类项 hover 的背景和边框颜色变化；
- Provider 卡片 hover 的边框和背景颜色变化；
- 输入框 focus 边框；
- 按钮 disabled、成功和错误状态；
- `aria-expanded`、`aria-label`、返回按钮和 Escape 行为。

如果需要进一步减少动态感，可以将 hover 的颜色 transition 设为即时变化，但本次建议不作为首批必改项，以免降低控件可感知性。

## 6. 风险与处理

### 风险 1：修改 `ModalShell` 影响其他弹窗

**处理**：必须采用显式 motion variant 或独立 class，默认模式保持原样。不要直接全局覆盖 `.modal--animated`。

### 风险 2：删除高度动画后 modal 高度突然变化

这是本次简化的预期结果，但需要确保：

- `.modal.settings-modal` 的 `max-height` 和 `overflow-y: auto` 仍生效；
- 页面切换后滚动位置符合预期；
- 视觉上不会出现内容超出视口。

如果产品仍希望保留一点过渡，可只保留短淡入，不恢复动态高度测量。

### 风险 3：Provider 条件渲染导致输入状态丢失

只要条件渲染发生在 `open/closed` 切换上，收起后输入内容可能从 DOM 消失，但 React state 中的 `drafts` 仍然保留；重新展开时输入值应由 state 重新渲染。需要用现有编辑、保存和 API Key 测试确认。

如果不希望输入中的未保存 DOM 状态被重建，可保留 wrapper 并使用 `display: none/block`，但仍移除高度动画。

### 风险 4：关闭动画变短后 fallback 时序不匹配

如果新增 simple motion variant，`ModalShell` 的关闭 fallback 不能继续固定依赖 400ms。建议让 fallback 根据 motion variant 设置，或使用不超过 CSS 动画时长的统一短值，确保 transitionend 和 fallback 都能可靠执行。

### 风险 5：Reduced Motion 行为分散

简化后应将 `prefers-reduced-motion` 逻辑集中到 ModalShell motion mode 和少量 CSS 规则，避免组件逻辑和 CSS 各自判断导致状态不一致。

## 7. 不建议的方案

### 7.1 直接删除所有 ModalShell 动画

会影响密码、确认、权限等其他弹窗，超出本需求范围。

### 7.2 只把动画时长从 320ms 改成 200ms

不能解决动态高度测量、弹簧缩放和多个 requestAnimationFrame 带来的实现复杂度；只是让同一套复杂逻辑更快。

### 7.3 只删除 CSS transition，保留 JS 高度测量

会留下无必要的 `frameHeight`、`useLayoutEffect`、`requestAnimationFrame` 和 transitionend 状态机，代码复杂度和潜在竞态仍然存在。

### 7.4 用 `setTimeout` 模拟更短动画

会增加时间依赖和测试不稳定性，不应使用 JS 定时器替代 CSS 或即时状态更新。
