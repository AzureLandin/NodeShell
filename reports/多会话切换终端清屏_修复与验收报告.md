## 1. 修复概述

针对多会话切换时原终端 xterm 实例被 React 卸载销毁（调用 `term.dispose()`）导致屏幕内容、光标位置、备用屏（TUI）和 scrollback 历史丢失的问题，本次修复调整了前端终端渲染策略：

1. **终端实例常驻挂载**：所有真实 SSH 会话（非 `pending-*` 占位状态）的 `TerminalView` 均长期保留在 React DOM 树中，不再随活动标签切换而卸载。
2. **显隐状态由 `visible` 属性驱动**：标签切换仅改变 `TerminalView` 的 `visible` 属性（内部通过 `display: block/none` 控制），切回活动状态时自动触发 `fit()` 与 `resize`，完整保留终端内部所有 VT 状态与滚动历史。
3. **连接态与终端容器解耦**：新建连接处于 `connecting` 或已有连接正在 `reconnect` 时，`.session-terminals` 容器仅设为隐藏（`display: none`），不触发卸载，杜绝慢连接期间已有终端被提前销毁。

## 2. 改动文件与代码详情

### 2.1 核心修复：`src/renderer/src/components/SessionTabs.tsx`

- **修改点 1**：导入 `isPendingSessionId` 用于过滤未完成握手的临时占位会话。
- **修改点 2**：重构 `session-terminal-area` 区域结构，拆分 `connecting` UI 与 `.session-terminals` 容器的生命周期。
- **修改点 3**：使用 `sessions.filter(!isPendingSessionId).map(...)` 渲染所有真实会话，并通过 `visible={session.sessionId === activeSessionId && !connecting}` 控制可见性。

```tsx
// src/renderer/src/components/SessionTabs.tsx

<div className="session-terminal-area">
  {sessions.length === 0 ? (
    <p className="main-placeholder">{t('session.placeholder')}</p>
  ) : (
    <>
      {activeSession &&
        (activeSession.status === 'disconnected' || activeSession.status === 'error') && (
          <div className="session-banner" role="alert">
            <span>
              {activeSession.status === 'error'
                ? (activeSession.errorMessage ?? t('session.error'))
                : t('session.disconnected')}
            </span>
            <button
              type="button"
              className="btn-primary btn-sm"
              onClick={() => onReconnect(activeSession)}
            >
              {t('session.reconnect')}
            </button>
          </div>
        )}

      {connecting && activeSession && (
        <div className="session-connecting" role="status" aria-live="polite">
          <p className="session-connecting-status">
            {t('auth.connectingStatus', {
              name: activeSession.title,
              host: activeSession.remoteHost ?? '—',
              port: activeSession.remotePort ?? '—'
            })}
          </p>
          {showSlowHint && (
            <p className="session-connecting-hint">{t('auth.connectingHint')}</p>
          )}
          {onCancelConnect && (
            <button type="button" className="btn-secondary btn-sm" onClick={onCancelConnect}>
              {t('auth.cancelConnect')}
            </button>
          )}
        </div>
      )}

      <div
        className="session-terminals"
        style={{ display: connecting ? 'none' : undefined }}
      >
        {sessions
          .filter((session) => !isPendingSessionId(session.sessionId))
          .map((session) => (
            <TerminalView
              key={session.sessionId}
              sessionId={session.sessionId}
              registerDataListener={registerDataListener}
              visible={session.sessionId === activeSessionId && !connecting}
              fontFamily={terminalFontFamily}
              fontSize={terminalFontSize}
              resolvedTheme={resolvedTheme}
              onFontSizeChange={onTerminalFontSizeChange}
            />
          ))}
      </div>
    </>
  )}
</div>
```

### 2.2 新增自动化测试：`tests/ui/session-terminal-persistence.test.tsx`

新增针对多终端实例生命周期的专用测试套件，全面覆盖以下场景：

1. **`retains xterm instances and does not dispose when switching between tabs`**：
   - 连接会话 A 与 B，反复切换标签 10+ 次；
   - 断言终端实例数量恒为 2，且两实例的 `dispose()` 调用次数始终为 0；
   - 断言切换后各实例的历史输出和状态完好保留。
2. **`routes background output to inactive session terminal instance`**：
   - 在会话 B 处于活动标签时，向后台会话 A 发送 `session:data` 数据流；
   - 断言数据准确写入会话 A 的 xterm 实例，不串线至 B，切回 A 时数据立即可见。
3. **`keeps existing terminal instances mounted during a slow pending connection`**：
   - 会话 A 已连接时，启动一个挂起连接的慢速会话 C；
   - 验证在 `connecting` 界面显示期间，会话 A 的终端实例不被销毁。
4. **`disposes only the closed session terminal instance and preserves remaining sessions`**：
   - 验证用户主动关闭会话 B 时，仅 B 对应的 xterm 实例执行 `dispose()` 恰好一次，会话 A 的实例保持运行。

### 2.3 解决验收中的 Go 单元测试失败：`internal/sshclient/sshclient_test.go`

- **问题现象**：在全仓库测试 `go test ./...` 中，`TestConnectHostNotFound` 失败（期望 `HOST_NOT_FOUND`，实际得到 `UNKNOWN: Connection closed by the server`）。
- **根因分析**：在配置了透明代理 / TUN 模式（如 Clash / Sing-box / fake-IP `198.18.0.x`）的开发或 CI 环境中，`does-not-exist.invalid` 未能直接返回 `net.DNSError`，而是被本地代理分配了虚假 IP；当拨号该虚假 IP 时，本地代理因上游解析失败立即切断连接（`io.EOF`），导致被判定为连接意外断开（`UNKNOWN`）。
- **修复方案**：遵循项目工程规范（*“测试不得依赖公网”*），在 `TestConnectHostNotFound` 中显式注入确定性的 mock `Dialer` 返回 `&net.DNSError{Name: "does-not-exist.invalid", Err: "no such host", IsNotFound: true}`。
- **验证结果**：测试完全密闭，不再受外部 DNS / 代理网络环境干扰，执行耗时 0.00s，全仓库 Go 测试 100% 通过。
