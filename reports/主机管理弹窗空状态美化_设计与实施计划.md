# 主机管理弹窗空状态美化：设计与实施计划

## 1. 背景与问题

当前截图对应的是主机管理弹窗的空状态。界面已经具备基本功能，但视觉层级和空间利用率较弱：

- 标题栏和空状态区域各有一个“新建主机”按钮，功能重复，注意力被分散。
- 空状态文案位于左上区域，缺少明确的视觉焦点，弹窗下半部分出现较大无效留白。
- 标题只有文字，缺少能够快速表达“主机/服务器管理”的图形识别点。
- 关闭按钮使用文本字符 `×`，点击区域和图标语义不够明确，和其他工具按钮的交互一致性不足。
- 空状态的说明信息较少，用户只能知道没有主机，无法获得下一步操作的清晰引导。

相关实现位置：

- `src/renderer/src/components/HostPickerModal.tsx`
- `src/renderer/src/App.css` 中的 `.host-picker-*`、`.host-empty` 和弹窗通用样式
- `src/renderer/src/i18n/locales/zh.json`
- `src/renderer/src/i18n/locales/en.json`

## 2. 设计目标

在不改变主机创建、编辑、连接和删除流程的前提下，让空状态更紧凑、可识别、可操作，并与现有深色工具型界面保持一致。

目标如下：

1. 首屏明确表达“当前没有已保存主机”。
2. 保留一个主操作入口，降低重复操作和视觉噪声。
3. 让弹窗高度由内容决定，避免空状态下的大面积无效留白。
4. 保持桌面端和窄窗口下的布局稳定，不产生标题、按钮或文案溢出。
5. 使用现有设计 Token 和图标体系，不新增图片资源或引入新的 UI 框架。

## 3. 推荐视觉方案

### 3.1 标题栏

- 标题左侧增加现有 FontAwesome 服务器/主机图标，图标使用 `aria-hidden="true"`，避免屏幕阅读器重复读取。
- 标题下方增加简短副标题，例如“管理已保存的远程主机”，英文文案同步维护。
- 标题与副标题组成左侧标题块，标题字号保持当前弹窗层级，副标题使用 `var(--text-subtle)`，不要使用过大的装饰性文字。
- 标题栏右侧保留“新建主机”作为唯一主操作，关闭按钮改为现有图标按钮风格，并保留 `aria-label`。

### 3.2 空状态主体

- 删除空状态中的重复“新建主机”按钮，仅保留标题栏主操作。
- 将空状态内容改为水平、垂直居中的布局，主体使用 `display: grid` 或等价的 flex 布局。
- 使用服务器图标或现有图标字体作为轻量视觉锚点，尺寸控制在紧凑范围内，避免使用大插画、渐变球或额外图片。
- 空状态文案拆分为主文案和辅助说明：主文案表达无主机，辅助说明说明可通过右上角按钮添加主机。
- 空状态主体增加合理的上下内边距，使弹窗有呼吸感，但避免为了填充空间而固定过高。

### 3.3 弹窗尺寸与层级

- 保持当前约 `520px` 的最大宽度，空状态下将高度收敛到内容所需范围；已有主机列表和主机表单仍允许按现有规则滚动。
- 继续使用 `var(--glass-bg)`、`var(--glass-border)`、`var(--shadow-modal)` 和现有圆角 Token，避免单独创建一套颜色。
- 标题栏分隔线保持低对比度，主按钮使用现有 `btn-primary`，关闭按钮采用图标按钮的固定点击区域。
- 不在页面区块外再包一层装饰卡片，空状态只作为弹窗内的内容区域。

## 4. 实施范围

### 4.1 组件修改

修改 `HostPickerModal.tsx`：

- 将标题文字包装为标题块，并加入服务器图标和副标题。
- 移除 `.host-empty` 中重复的“新建主机”按钮。
- 将空状态主体调整为图标、主文案、辅助说明的结构。
- 关闭按钮改用项目已有的图标组件或图标字体；如果项目当前没有可复用关闭图标，再使用最小化的本地 CSS/字符方案，并保持无障碍标签。
- 保持 `setFormMode({ type: 'create' })`、连接中禁用状态、Escape 关闭和表单覆盖逻辑不变。

### 4.2 样式修改

修改 `App.css`：

- 调整 `.host-picker-header` 的标题块、操作区和窄窗口换行规则。
- 新增明确的空状态类，例如 `.host-empty-icon`、`.host-empty-copy`、`.host-empty-description`，并限定稳定的尺寸、间距和文本换行行为。
- 更新 `.host-empty` 的对齐方式、最小高度和 padding；避免使用依赖视口宽度缩放的字体设置。
- 调整 `.host-picker-modal` 的高度/最大高度策略，区分空状态、列表和表单场景，确保列表场景不被压缩。
- 补充 `@media` 窄窗口规则，以及 `prefers-reduced-motion` 下无额外动画的处理。

### 4.3 国际化

在 `zh.json` 和 `en.json` 中补充副标题与空状态辅助说明文案。文案应短小、可翻译，不将视觉或快捷键说明直接写进界面。

## 5. 交互与无障碍要求

- 标题栏主按钮仍可直接打开新建表单；禁用条件继续沿用 `connecting`。
- 关闭按钮具备明确的 `aria-label`、可见 focus 状态和不小于约 `32px` 的可点击区域。
- 键盘 Tab 顺序为：新建主机、关闭按钮；进入创建表单后沿用表单自身顺序。
- Escape 行为保持现状：普通状态关闭弹窗，表单状态退出表单，连接中不误关闭。
- 空状态图标设置为装饰性内容；真正信息通过可读文本表达。
- 主、副文案使用足够的对比度，长文案在窄窗口可换行且不遮挡按钮。

## 6. 验收标准

### 视觉验收

- 空状态下界面只出现一个“新建主机”主操作入口。
- 标题栏能同时显示主机图标、标题、副标题、创建按钮和关闭按钮，元素之间无重叠。
- 空状态内容在主体区域居中，留白均衡，弹窗不会出现不必要的超大高度。
- 深色主题下颜色、边框、阴影和圆角与现有弹窗一致；不新增孤立的颜色体系。
- 已有主机列表和新建/编辑表单的可用性与布局不发生回归。
- 窄窗口下标题、文案和按钮能换行或收缩，不能横向溢出。

### 功能验收

- 点击标题栏“新建主机”可以正常进入创建表单。
- 创建、取消、编辑、删除、连接流程保持正常。
- 连接中按钮和关闭按钮的禁用行为保持正确。
- 鼠标点击遮罩、Escape 和关闭按钮的行为符合现有规则。

### 自动化与手工验证

- 补充或更新 `HostPickerModal` 的组件测试，至少覆盖空状态单一主按钮、打开创建表单和关闭行为。
- 执行项目现有类型检查、测试和构建命令。
- 在桌面宽度、窄窗口、深色主题及支持的浅色主题下分别截图检查。
- 使用键盘完成 Tab、Enter、Escape 操作，确认 focus 可见且顺序合理。

## 7. 风险与控制

- **弹窗高度回归**：列表和表单场景依赖固定/最大高度策略，修改时只对空状态收敛，并验证滚动容器仍可用。
- **图标体系不一致**：优先复用项目已安装的 FontAwesome 图标，不新增图标依赖。
- **国际化溢出**：中英文分别检查标题块和空状态说明，必要时允许自然换行。
- **业务回归**：只调整展示结构和样式，不改 `onCreate`、`onUpdate`、`onRemove`、`onConnect` 的调用契约。

## 8. 实施顺序

1. 先确认项目现有图标组件/API及弹窗 Token 的使用方式。
2. 修改 `HostPickerModal.tsx` 的标题块与空状态结构。
3. 修改 `App.css`，完成桌面端、窄窗口和主题适配。
4. 补充中英文文案与组件测试。
5. 执行类型检查、测试和构建，并进行人工交互验收。

## 9. 非目标

- 不重做主机列表卡片的整体信息架构。
- 不改变主机配置数据结构、持久化逻辑或连接流程。
- 不新增远程图片、插画资源或第三方 UI 组件库。
- 不在本次迭代加入搜索、分组、导入导出等主机管理功能。
