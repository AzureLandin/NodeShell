# 侧栏展开收起动画优化：设计与实施计划

## 1. 背景与问题

当前左侧监控侧栏和右侧 Agent 面板都采用“固定内部宽度 + 外层宽度过渡”的收起方式。相关实现为：

- `src/renderer/src/App.tsx` 中的 `.sidebar` 和 `.agent-dock` 状态类切换
- `src/renderer/src/App.css` 中 `.sidebar`、`.sidebar.is-collapsed`、`.agent-dock` 和 `.agent-dock.is-collapsed`

现有动画不自然的主要原因：

- 外层宽度从 `240px` 或 `360px` 直接过渡到 `0`，主内容区域会在整个动画过程中持续发生 flex 布局重排。
- 宽度和外边距使用 `var(--ease-spring)`，侧栏属于应用框架布局，回弹效果容易显得拖沓或不稳定。
- 内部内容没有独立的淡入、淡出和位移动画，收起时会随着容器变窄被裁切，展开时则可能突然出现。
- 收起状态直接将 `border-width` 设为 `0`，边缘会出现跳动或视觉厚度变化。
- 终端主区域随侧栏宽度逐帧变化，可能触发连续尺寸同步，产生终端内容抖动、光标跳动或边界移动不均匀。

## 2. 设计目标

在不改变侧栏开关逻辑、内容持久化、键盘可访问性和终端功能的前提下，建立稳定、克制、可预测的侧栏动效。

目标如下：

1. 展开和收起过程无明显回弹、停顿或突然跳变。
2. 侧栏外壳和内部内容分层动画，避免内容被逐字裁切。
3. 减少侧栏动画对终端主区域布局和尺寸同步的干扰。
4. 左侧监控侧栏和右侧 Agent 面板使用统一的动效节奏。
5. 保留 `aria-hidden`、`inert` 和 `prefers-reduced-motion` 行为。

## 3. 推荐动效方案

### 3.1 外壳宽度动效

侧栏外壳负责布局空间，内部内容负责视觉进入和退出。宽度过渡不再使用弹簧曲线，建议采用稳定的 ease-out 曲线：

- 展开：`220ms - 260ms`
- 收起：`180ms - 220ms`
- 推荐曲线：`cubic-bezier(0.2, 0.8, 0.2, 1)`
- 宽度与外边距使用相同的时长和曲线，避免侧栏与主内容之间产生错位

应用框架布局不使用明显回弹，保证终端、列表和按钮的位置变化可预测。

### 3.2 内部内容动效

`.sidebar-inner` 和 `.agent-dock-inner` 保持稳定的固定宽度，由外层容器负责裁切。内部内容单独增加：

- 展开时：`opacity: 0 -> 1`，并从侧边轻微位移约 `6px` 回到正常位置。
- 收起时：`opacity: 1 -> 0`，同时向收起方向位移约 `6px`。
- 内容动效时长控制在 `100ms - 140ms`。
- 展开时可延迟约 `40ms - 60ms` 再显示内容，避免内容在窄宽度阶段提前露出。
- 收起时先淡出内容，再收缩外壳，避免出现被容器强行截断的效果。

左侧和右侧的位移方向分别对应各自的展开方向：

- 左侧监控栏从左向右展开，收起时向左退出。
- 右侧 Agent 栏从右向左展开，收起时向右退出。

### 3.3 边框、阴影和圆角

- 不再通过 `border-width: 0` 隐藏边框，避免边缘厚度变化造成跳动。
- 保持固定边框宽度，收起状态将边框颜色和阴影透明化，或由外层布局容器统一承担边界。
- 圆角保持稳定，不在收起过程中切换圆角值。
- 阴影可在内容淡出后快速淡出，避免侧栏已经不可见但阴影仍残留。

## 4. 布局重排与终端稳定性

### 4.1 推荐方案：布局占位与视觉滑出分离

优先评估增加一个侧栏占位外层：

- 外层负责管理主内容需要的布局宽度。
- 侧栏自身使用 `transform` 完成视觉滑入和滑出。
- 主区域避免在视觉动画每一帧都发生宽度变化。
- 动画结束后再释放收起状态的占位空间。

该方案可以降低终端区域连续 resize 的概率，适合终端内容对尺寸变化敏感的场景。

### 4.2 兼容方案：保留宽度过渡并降低同步频率

如果当前布局结构不适合增加占位层，则保留现有宽度过渡，但需要：

- 仅在开关状态变化或动画结束后同步终端尺寸。
- 不要因 CSS 宽度每一帧变化而重复触发 xterm resize。
- 用 `transitionend` 或已有布局同步机制确认动画完成。
- 重点验证终端光标、换行宽度、滚动条和当前会话内容不发生异常。

最终实现前应通过实际运行效果决定采用哪一种方案。

## 5. 实施范围

### 5.1 `App.tsx`

- 保持 `monitorOpen` 和 `agentOpen` 的状态逻辑不变。
- 保持侧栏始终挂载，避免关闭时丢失监控数据、Agent 对话和事件监听。
- 继续维护：
  - `aria-hidden={!open}`
  - `inert={!open ? true : undefined}`
- 如需区分“打开中、已打开、关闭中、已关闭”，可增加最小化的动画阶段状态，但不能破坏现有点击切换行为。
- 如采用布局占位方案，只增加必要的包装层，不重构侧栏内容组件。

### 5.2 `App.css`

调整范围：

- `.sidebar` 和 `.agent-dock` 的宽度、外边距、边框和阴影过渡。
- `.sidebar-inner` 和 `.agent-dock-inner` 的透明度及方向性位移动效。
- `.is-collapsed` 状态下的 `pointer-events`、透明边框和阴影处理。
- 必要时新增 `.sidebar-shell`、`.agent-dock-shell` 或等价的布局占位类。
- 为打开、关闭和快速重复切换补充稳定的状态选择器。
- 在 `@media (prefers-reduced-motion: reduce)` 中关闭宽度、透明度和 transform 过渡，直接显示最终状态。

不建议对 `width: auto`、复杂内容高度或大量子元素逐一设置动画；侧栏应只动画必要的外壳属性和内部内容属性。

## 6. 交互与无障碍要求

- 展开/收起按钮的 `aria-label`、`title` 和 `aria-pressed` 语义保持正确。
- 侧栏收起后继续使用 `aria-hidden` 和 `inert`，确保内容不可聚焦、不可点击。
- 动画期间快速连续点击不能导致状态与视觉结果相反。
- 动画过程中不改变内部内容的 DOM 顺序，避免焦点跳转。
- `prefers-reduced-motion: reduce` 下不保留延迟、淡入或位移动效。
- 不能依赖颜色或动画作为唯一状态表达方式，按钮的 pressed 状态需要由属性和颜色共同表达。

## 7. 验收标准

### 视觉验收

- 左侧监控栏打开和收起时无明显回弹、顿挫或边缘跳动。
- 右侧 Agent 栏使用同样自然的节奏，但位移方向正确。
- 收起过程中内部文字、图标和表单不会出现逐字裁切或突然消失。
- 展开时内容不会在侧栏尚未展开完成前提前溢出。
- 边框、圆角和阴影不会闪烁或出现厚度突变。
- 主终端区域的位置变化平滑，不出现明显抖动、闪烁或尺寸连续跳变。

### 功能验收

- 点击左侧监控按钮可以稳定切换侧栏状态。
- 点击 Agent 开关可以稳定切换右侧面板状态。
- 快速连续打开/收起后，最终状态、按钮 pressed 状态和可访问属性一致。
- 侧栏收起后不可通过 Tab 聚焦内部控件。
- 已打开的监控内容、Agent 对话内容和事件监听不会因动画丢失。
- 终端输入、滚动、换行和会话切换不受动画影响。

### 测试与手工验证

- 执行现有类型检查、测试和构建命令。
- 在空状态、列表较长、Agent 有历史消息和终端有长文本时分别测试。
- 在普通桌面宽度和较窄窗口下测试。
- 反复快速点击开关按钮，观察动画是否可恢复到正确最终状态。
- 使用键盘验证焦点、Tab 顺序、Enter 和无障碍属性。
- 在开启系统减少动画设置后确认侧栏直接切换且布局正常。
- 使用浏览器性能面板或运行时观察确认动画期间没有异常高频 resize。

## 8. 风险与控制

- **终端 resize 回归**：优先采用布局占位与视觉滑出分离；若保留宽度动画，则将终端尺寸同步限制在状态变化或动画完成时。
- **动画阶段状态复杂化**：只有在 CSS 状态无法实现先淡出再收缩时才增加阶段状态，并集中处理清理和快速重复点击。
- **侧栏内容丢失**：继续保持侧栏 DOM 挂载，不使用 `display: none` 直接切断过渡或卸载内容。
- **焦点泄漏**：收起状态继续使用 `inert` 和 `aria-hidden`，并通过键盘测试确认内部控件不可访问。
- **两侧节奏不一致**：抽取或复用同一组动效 Token，差异只体现在位移方向和布局方向。
- **性能问题**：优先使用 `transform` 和 `opacity` 做视觉动画，减少对复杂内容和终端区域的重复布局计算。

## 9. 实施顺序

1. 记录当前左侧和右侧侧栏的打开、收起、快速重复点击及终端 resize 行为，建立基线。
2. 统一侧栏动效时长和缓动 Token，移除宽度动画上的弹簧曲线。
3. 为内部内容增加方向性淡入、淡出和轻微位移动效。
4. 去除 `border-width` 动画式切换，统一边框、阴影和圆角处理。
5. 评估并实现布局占位与视觉滑出分离；若不适用，则采用动画结束后同步终端尺寸的兼容方案。
6. 完善快速重复操作、无障碍和减少动画模式。
7. 执行测试、构建和多窗口尺寸手工验收。

## 10. 非目标

- 不改变侧栏的业务内容、数据加载和状态管理。
- 不重新设计监控面板、端口映射面板或 Agent 面板内部信息架构。
- 不新增第三方动画库。
- 不通过大幅缩放、弹跳或复杂背景动画制造视觉效果。
