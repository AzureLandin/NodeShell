# Electron Backend Removal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use compose:subagent to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the Electron/Node/ssh2 runtime and MCP relay while preserving the existing React UI and proving the Wails adapter's key interactions.

**Architecture:** Keep `src/renderer`, `src/shared/types.ts`, `src/shared/ipc-error.ts`, and the Wails `window.api` adapter as the sole frontend boundary. Delete the old main/preload backend and its tests, then reduce npm/TypeScript/ESLint configuration to the Vite/Wails application. Add focused renderer interaction tests without changing component structure or visual styling.

**Tech Stack:** Go 1.26, Wails v2.13, React 19, Vite 7, TypeScript, Vitest, Testing Library, jsdom.

## Global Constraints

- Preserve the existing React/Vite/xterm UI, visual structure, wording, shortcuts, themes, i18n, and state model.
- The shipped application must not depend on Electron, Node.js, `ssh2`, or the Node MCP relay.
- Keep the thin `window.api` compatibility layer; do not introduce a second handwritten backend API surface.
- Do not redesign the UI or add product functionality.
- Do not change CI/release workflows in this task; T1.9 owns three-platform CI and packaging.
- Do not create commits; the user has not requested commits.
