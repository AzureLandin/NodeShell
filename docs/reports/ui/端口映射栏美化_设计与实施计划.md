# 端口映射栏美化：设计与实施计划

## 1. 背景与问题

当前端口映射面板位于左侧边栏的“端口”页签中，截图显示面板可以正常表达基础功能，但视觉层级和状态反馈较弱：

- “监控”和“端口”页签只有文字，当前页签的识别度有限。
- “刷新”和“映射所选”按钮缺少图标、选中数量和当前可用状态的辅助信息。
- 未连接会话时，说明文案靠左且在窄面板中换行，形成突兀的大面积空白。
- 已连接但没有监听端口、正在加载、加载失败等状态没有形成明确的视觉区分。
- 端口列表需要同时表达远程地址、本地映射地址、映射状态和行级操作，现有结构在窄面板内容易显得拥挤。

相关实现位置：

- `src/renderer/src/components/TunnelPanel.tsx`
- `src/renderer/src/components/SidebarPanel.tsx`
- `src/renderer/src/App.css` 中的 `.sidebar-tunnels`、`.tunnel-*` 样式
- `src/renderer/src/i18n/locales/zh.json`
- `src/renderer/src/i18n/locales/en.json`

## 2. 设计目标

在不改变端口发现、批量映射、复制、本地打开和停止映射行为的前提下，提升端口面板的信息密度、状态可读性和窄栏操作效率。

目标如下：

1. 用户能够快速知道当前页签、当前会话连接状态和端口数量。
2. 空状态能够区分未连接、无端口、加载中和失败，而不是只显示一段说明文字。
3. 端口条目清晰展示远程端口、绑定地址、本地地址和映射状态。
4. 批量操作和行级操作有明确的主次关系，并在不可用时给出稳定的禁用反馈。
5. 使用现有设计 Token、图标体系和国际化机制，保持深色工具型界面的一致性。

## 3. 推荐视觉方案

### 3.1 页签

- “监控”和“端口”页签增加对应的现有图标，例如活动状态图标和网络转发图标。
- “端口”页签可以显示发现数量，例如“端口 3”；数量没有数据时不显示或显示为 `0`，需要结合现有文案风格确定。
- 保留当前蓝色激活指示线，但将指示线收敛到页签内容区域，避免横跨整个面板造成过强分割。
- 激活页签使用更高的文字对比度，未激活页签使用次级文字颜色。
- 页签仍使用 `role="tab"` 和 `aria-selected`，图标设置为装饰性内容。

### 3.2 面板标题与工具栏

在工具栏上方增加紧凑的面板标题区：

- 标题显示端口映射图标和“端口映射”。
- 副信息显示当前会话状态，例如“已连接”或“未连接”；不展示无法从现有数据可靠取得的信息。
- “刷新”使用刷新图标加文字，保留完整 Tooltip/无障碍名称。
- “映射所选”继续作为唯一主操作，可显示当前数量，例如“映射所选（2）”。
- 没有选中未映射端口时，主按钮保持禁用；连接中、刷新中和批量操作中的状态需要明确体现。
- 工具栏允许换行，但按钮不能因文本变化发生尺寸跳动。

### 3.3 状态摘要

工具栏下方增加轻量摘要，而不是增加装饰性卡片：

```text
发现 3 个端口 · 已映射 1 个
```

摘要只使用较小字号和次级颜色，避免抢占端口列表的视觉重点。数量应来自当前 `listeners` 与 `tunnels` 数据，并正确处理重复映射和无效映射。

### 3.4 空状态

空状态改为面板主体中的居中布局，使用现有图标字体作为视觉锚点，不新增图片或插画资源。

未连接状态：

```text
       [端口图标]
      尚未连接会话
  连接会话后可发现远程监听端口
```

已连接但无监听端口状态：

```text
       [端口图标]
      暂无可映射端口
    刷新后将重新检测远程服务
```

加载中状态：

- 使用小型加载指示器或现有加载状态样式。
- 显示“正在检测远程端口...”等简短文案。
- 不使用会造成布局跳动的大型动画。

失败状态：

- 使用警告图标和错误颜色。
- 显示错误信息，并提供“重试”操作；重试仍复用现有 `refresh` 行为。
- 错误文本需要允许换行，不得横向撑破窄面板。

空状态主体应有均衡的上下间距，但不能通过固定过高的最小高度制造大面积无效留白。

### 3.5 端口列表

有端口时，将每个端口整理为紧凑、可扫描的条目：

未映射：

```text
[ ]  3000
     0.0.0.0                 未映射
```

已映射：

```text
[✓]  3000
     0.0.0.0  ->  127.0.0.1:3000    已映射
                              复制  打开  停止
```

具体要求：

- 远程端口使用等宽数字和较高亮度，绑定地址使用次级颜色。
- 本地地址使用等宽字体，支持省略但保留 `title` 或 Tooltip 查看完整值。
- 映射成功显示绿色状态标记，映射中显示进行中状态，失败沿用错误状态表达。
- 行级操作按钮使用图标加 Tooltip；“停止”可以保留文字或图标加文字，以避免误操作。
- 复用当前 checkbox 选择模型和 `tunnel-pick` 的可访问标签。
- 条目使用轻量边框或背景层次区分，不嵌套多层卡片，不增加过度阴影。
- 端口、地址和操作区域设置 `min-width: 0`、稳定间距和换行规则，防止窄面板溢出。

## 4. 实施范围

### 4.1 `TunnelPanel.tsx`

- 增加面板标题、连接状态和状态摘要的展示结构。
- 为刷新、批量映射、单项映射、复制、打开和停止按钮接入现有图标体系。
- 将当前条件分支整理为明确的 loading、error、unusable、empty 和 list 状态。
- 保持以下业务行为和数据契约不变：
  - `window.api.tunnels.discover(activeSessionId)`
  - `window.api.tunnels.list(activeSessionId)`
  - `window.api.tunnels.start(activeSessionId, bind, port)`
  - `window.api.tunnels.stop(activeSessionId, tun.id)`
  - 现有 `selected`、`busyKey` 和 `activeSessionId` 状态语义
- 批量映射仍按当前选中端口执行，避免在本次视觉改造中改变并发策略或错误处理策略。

### 4.2 `SidebarPanel.tsx`

- 仅在现有页签结构允许的范围内增加图标和数量信息。
- 保持 `role="tablist"`、`role="tab"`、`aria-selected` 和面板切换行为。
- 不改变监控页签的数据加载和显示逻辑。

### 4.3 `App.css`

新增或调整以下样式范围：

- `.sidebar-tabs`、页签图标和数量标记。
- `.sidebar-tunnels` 的内容间距、滚动和空状态占位策略。
- `.tunnel-heading`、`.tunnel-status`、`.tunnel-summary`。
- `.tunnel-empty`、`.tunnel-empty-icon`、`.tunnel-empty-copy`、`.tunnel-empty-description`。
- `.tunnel-row`、`.tunnel-pick`、`.tunnel-live` 和状态标记。
- 工具按钮、图标按钮的 focus、disabled、hover 状态。
- 窄面板媒体查询和 `prefers-reduced-motion` 规则。

颜色、边框、阴影、圆角和字体优先复用现有 `var(--*)` Token；不新增一套独立主题颜色。

### 4.4 国际化

在 `zh.json` 和 `en.json` 中补充：

- 面板标题及连接状态文案。
- 未连接、无端口、加载中和失败状态文案。
- 端口数量、已映射数量和状态标记文案。
- 图标按钮的 Tooltip/`aria-label` 文案。

所有新增文案都应保持简短，英文版本需要单独检查窄栏宽度下的换行效果。

## 5. 交互与无障碍要求

- 刷新按钮在未连接、加载中时禁用；刷新过程中需要有可感知的 busy 状态。
- 批量映射按钮只对选中的未映射端口生效，已映射端口不重复执行。
- 行级映射、停止、复制和打开按钮继续对应当前单项操作。
- 所有仅图标按钮都必须有 `aria-label` 和 Tooltip。
- Checkbox 与端口信息保持关联，`aria-label` 继续包含绑定地址和端口号。
- 键盘 Tab 顺序应从页签进入工具栏，再进入端口条目和行级操作。
- 颜色不能作为唯一状态表达方式，映射状态需要同时有文字或图标。
- 错误文案可读、可换行，不遮挡重试按钮或其他端口条目。

## 6. 验收标准

### 视觉验收

- 当前页签清晰可识别，端口数量信息不会导致文字溢出。
- 未连接、已连接无端口、加载中和错误四种状态具有明显但克制的视觉区别。
- 空状态主体居中，面板不再出现截图中的大面积无意义留白。
- 工具栏主次关系明确，禁用状态不会与正常状态混淆。
- 端口条目能够一眼区分远程地址、本地映射地址和映射状态。
- 深色主题下颜色、边框、圆角和阴影与现有侧边栏一致。
- 窄窗口下按钮、英文文案、地址和错误信息不发生重叠或横向溢出。

### 功能验收

- 切换监控/端口页签行为不变。
- 刷新仍能重新发现远程监听端口并保留有效选择状态。
- 单项映射、批量映射、停止映射、复制本地地址和打开本地地址均正常。
- 映射中的条目操作禁用逻辑正确，操作结束后状态及时更新。
- 未连接会话时不会调用端口发现、列表或映射接口。
- 错误信息和重试行为正常，重试后能够恢复列表或空状态。

### 测试与手工验证

- 补充或更新 `TunnelPanel` 组件测试，覆盖四种状态、单项操作、批量选择和已映射条目。
- 执行项目现有类型检查、测试和构建命令。
- 在正常桌面宽度和窄侧边栏宽度下检查布局。
- 使用键盘验证页签切换、Checkbox 选择、按钮聚焦和 Enter 操作。
- 验证支持的深色/浅色主题，以及 `prefers-reduced-motion` 场景。

## 7. 风险与控制

- **状态展示与真实数据不一致**：数量和状态摘要必须从 `listeners`、`tunnels` 的当前状态派生，不引入独立且容易过期的计数状态。
- **窄栏布局溢出**：地址、错误信息和英文文案使用 `min-width: 0`、省略和自然换行，并用不同宽度截图验证。
- **操作误触**：停止、打开等操作保留清晰文字或 Tooltip，不用难以识别的纯图标替代高风险操作。
- **业务回归**：本次只调整展示结构、样式和文案，不修改 tunnels API 调用契约和状态转换。
- **动画干扰**：加载状态只使用现有轻量动画，并遵守 `prefers-reduced-motion`。

## 8. 实施顺序

1. 确认项目现有图标组件、Tooltip 组件和颜色 Token 的使用方式。
2. 先改造 `TunnelPanel.tsx` 的标题、摘要和状态结构。
3. 调整 `SidebarPanel.tsx` 的页签图标与数量展示。
4. 在 `App.css` 中完成空状态、列表条目、按钮状态和窄栏适配。
5. 补充中英文国际化文案及组件测试。
6. 执行类型检查、测试和构建，并完成多状态、多宽度的人工验收。

## 9. 非目标

- 不改变 SSH 隧道的发现、建立、停止和本地打开逻辑。
- 不在本次迭代加入端口搜索、排序、分组、持久化或自动重连。
- 不新增第三方 UI 框架、远程图片或大型插画资源。
- 不重做整个侧边栏的导航和监控页面。
