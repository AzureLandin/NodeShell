# 主机管理无分页布局与美化：设计与实施计划

## 1. 背景与问题

当前主机管理弹窗使用单一内容区域承载主机列表和新建/编辑表单。主机表单采用纵向单列结构，在窗口高度有限时需要长距离滚动；当主机数量增加后，如果继续采用分页，用户还需要在列表页之间来回切换，影响主机查找、编辑和连接效率。

当前相关实现位置：

- `src/renderer/src/components/HostPickerModal.tsx`
- `src/renderer/src/components/HostForm.tsx`
- `src/renderer/src/App.css` 中的 `.host-picker-*`、`.host-item`、`.host-form-*` 样式
- `src/renderer/src/i18n/locales/zh.json`
- `src/renderer/src/i18n/locales/en.json`

截图中还可以看到以下体验问题：

- 表单字段纵向排列，内容高度较长。
- 表单滚动条占据明显视觉空间，用户需要滚动才能找到底部操作。
- 主机列表和编辑内容没有同时呈现，编辑主机时容易失去当前列表上下文。
- 主机信息层级仍可进一步压缩，名称、地址、用户和认证方式没有形成快速扫描结构。

## 2. 设计目标

在不引入分页、不改变主机配置数据和连接行为的前提下，将主机管理改造成适合多主机长期使用的单页管理界面。

目标如下：

1. 所有主机在一个界面中通过搜索和滚动访问，不使用分页。
2. 列表和编辑区同时存在，编辑主机时保留主机列表上下文。
3. 通过两列字段和信息分组降低表单高度。
4. 操作按钮始终可见，避免用户滚动到页面底部寻找保存操作。
5. 窄窗口下自动降级为单栏布局，不产生横向溢出或内容重叠。
6. 保持现有创建、编辑、删除、连接、连接中禁用和确认弹窗行为。

## 3. 推荐整体方案

采用“**左侧主机列表 + 右侧编辑区**”的主从布局：

```text
┌──────────────────────────────────────────────┐
│  主机管理                         [+ 新建主机] │
│  管理已保存的远程主机                         │
├───────────────┬──────────────────────────────┤
│ 搜索主机       │ 新建主机                      │
│               │ 基本信息                       │
│ ● 生产服务器  │ 名称                          │
│   root@prod   │ [                            ] │
│               │ 主机              端口         │
│ ● 测试服务器  │ [              ] [22        ] │
│   root@test   │ 用户名                        │
│               │ [                            ] │
│               │ 认证方式  [密码] [私钥]        │
│               │                              │
│               │              [取消] [保存并连接]│
└───────────────┴──────────────────────────────┘
```

默认状态展示主机列表；点击“新建主机”或某条主机的编辑操作后，在右侧打开对应表单。创建或编辑不再跳转到新的分页页面。

## 4. 主机列表设计

### 4.1 无分页访问

- 列表区域使用独立纵向滚动容器。
- 顶部增加搜索框，按主机名称、地址或用户名进行本地过滤。
- 保留当前主机条目结构，改为更紧凑的列表项。
- 不新增分页器、页码按钮或下一页/上一页操作。
- 主机数量较少时直接渲染列表；未来数量达到较大规模时，可使用虚拟列表提升性能，仍不改变用户的无分页体验。

### 4.2 列表项信息层级

每条主机建议展示：

```text
┌──────────────────────┐
│ ● 生产服务器          │
│   root@192.168.1.20   │
│   SSH · 22            │
└──────────────────────┘
```

- 使用服务器图标或首字母头像作为识别点。
- 主机名称使用主要文字颜色和较高字重。
- 地址、用户名和端口使用等宽字体，便于快速比较。
- 增加连接状态点或状态标签：已连接、未连接、连接中。
- 当前选中主机使用背景色和边框高亮，不能只依赖颜色表达。
- 编辑和删除按钮默认保持低干扰，可在悬停、聚焦或选中时显示。
- 删除继续使用危险色和确认弹窗，避免误操作。

### 4.3 空状态

没有主机时不显示空的列表框架，使用居中引导：

```text
             [服务器图标]

           暂无已保存主机
       添加一台主机开始远程连接

              [+ 新建主机]
```

空状态中的“新建主机”可以作为唯一主操作；有主机时只保留标题栏的“新建主机”，避免重复按钮。

## 5. 编辑区设计

### 5.1 单页分组表单

将当前长单列表单改为分组表单：

**基本信息**

- 名称：整行展示。
- 主机和端口：同一行的两列布局。
- 用户名：整行展示，或在空间足够时与端口组合布局。

**认证配置**

- 认证方式使用分段控件：`密码` / `私钥`。
- 密码认证只显示密码字段。
- 私钥认证显示私钥路径和浏览按钮。
- 浏览按钮优先使用文件夹图标加 Tooltip，保留可读的无障碍名称。

通过字段分组和两列布局降低表单高度，同时保持字段顺序符合填写习惯。

### 5.2 固定底部操作栏

编辑区底部增加固定操作栏：

```text
────────────────────────────
                         取消   保存并连接
```

- 表单内容区域独立滚动，操作栏不随内容滚出视野。
- 保存按钮使用主色，取消按钮使用次要层级。
- 保存中显示 loading 或保存中状态，并禁用相关输入。
- 有未保存变更时可以显示轻量未保存提示，但不阻塞现有取消和关闭行为。
- 新建模式沿用当前“创建并连接”行为；编辑模式沿用当前保存行为。

## 6. 弹窗尺寸与响应式布局

### 6.1 桌面端

当前约 `520px` 的弹窗宽度不适合主从布局，建议调整为：

- 宽度：`min(720px - 820px, calc(100vw - 32px))`
- 高度：`min(78vh, 680px)`
- 左侧列表宽度：约 `220px - 260px`
- 右侧编辑区占据剩余空间
- 列表和编辑内容分别拥有滚动容器

弹窗标题栏保持服务器图标、标题、副标题、新建按钮和关闭按钮的结构。

### 6.2 窄窗口

当可用宽度不足以容纳两栏时自动切换为单栏：

1. 标题栏
2. 搜索和主机列表
3. 当前主机编辑区
4. 固定底部操作栏

窄窗口下：

- 不使用固定像素宽度强行撑开内容。
- 主机列表和编辑区可以通过现有模式状态切换显示，但不引入分页概念。
- 输入框、按钮、标题和国际化文案允许自然换行。
- 禁止列表、表单、操作按钮互相覆盖。

## 7. 视觉美化规范

- 继续使用现有 `var(--glass-bg)`、`var(--glass-border)`、`var(--bg-card)`、`var(--border-default)` 和按钮 Token。
- 减少多层嵌套卡片，列表项使用轻边框和浅背景层级即可。
- 输入框统一高度和圆角，保持标签、输入控件和帮助信息的垂直节奏。
- 分组标题使用较小字号和清晰层级，不使用过大的标题填充空间。
- 主机名、地址、用户名和端口采用稳定的文字宽度策略，长地址省略并通过 Tooltip 查看完整值。
- 主要按钮只保留一个明确的主色入口，避免新建、保存和连接按钮同时争夺视觉重点。
- 使用现有 FontAwesome 图标，不新增图片资源或第三方 UI 组件库。
- 不使用大面积渐变、装饰性光斑或过重阴影，保持工具型界面的高信息密度。

## 8. 实施范围

### 8.1 `HostPickerModal.tsx`

- 将当前“列表/表单二选一”结构调整为主从布局容器。
- 增加列表区域、搜索区域和编辑区域的结构。
- 保持 `formMode` 的创建/编辑语义；选中主机时将对应主机传递给编辑表单。
- 空状态只在没有主机时展示，并保留新建入口。
- 保持连接中状态下按钮禁用和当前连接目标展示。
- 保持删除确认弹窗的显示和处理流程。

### 8.2 `HostForm.tsx`

- 为字段增加“基本信息”和“认证配置”分组结构。
- 将主机与端口等适合并列的字段改为响应式两列布局。
- 将底部操作按钮放入固定操作栏或由外层编辑区提供固定容器。
- 保持现有字段校验、密码处理、私钥选择和提交参数不变。
- 保持新建和编辑模式下密码、私钥和提交文案的现有语义。

### 8.3 `App.css`

新增或调整以下样式范围：

- `.host-picker-modal` 的宽度、高度和布局方向。
- `.host-picker-content`、`.host-directory`、`.host-editor` 等主从布局容器。
- `.host-search`、`.host-directory-list` 和列表滚动行为。
- `.host-item` 的紧凑信息层级、选中状态和行级操作。
- `.host-form`、表单分组、响应式字段网格和固定操作栏。
- 空状态、错误状态、loading 状态和窄窗口媒体查询。
- 键盘 focus、disabled 和 `prefers-reduced-motion` 状态。

所有新增样式优先复用现有设计 Token，避免影响其他弹窗和表单。

### 8.4 国际化

在 `zh.json` 和 `en.json` 中补充：

- 搜索主机和无搜索结果文案。
- 主机数量、连接状态和列表辅助信息。
- 基本信息、认证配置等表单分组标题。
- 选中主机、未保存状态和编辑区提示文案。
- 搜索、编辑、关闭和浏览等图标按钮的 Tooltip/`aria-label`。

英文文案需要在窄窗口下单独验证，确保不会撑破列表或操作栏。

## 9. 交互与无障碍要求

- 搜索框输入后立即过滤本地列表，不触发远程连接或持久化操作。
- 选择列表项后编辑区更新，未保存表单切换时需要沿用项目现有的处理策略，不能静默丢失用户输入。
- 新建、编辑、取消、保存、连接、删除流程保持语义清晰。
- 列表项和表单控件具有稳定的 Tab 顺序。
- 当前选中主机使用 `aria-current` 或等价语义；列表项不可只依靠颜色表达选中状态。
- 搜索无结果时提供清晰文案和清除搜索的操作。
- 图标按钮必须提供 `aria-label` 和 Tooltip。
- 滚动区域不能截断键盘 focus 轮廓。
- 窄窗口下文本可换行，不能出现内容、按钮和滚动条重叠。

## 10. 验收标准

### 视觉验收

- 主机列表不显示分页器，所有主机通过滚动和搜索访问。
- 桌面端能够同时看到主机列表和编辑区，编辑时不丢失列表上下文。
- 表单字段分组清晰，名称、主机、端口、用户名和认证方式的布局紧凑。
- 操作栏固定可见，不需要滚动到表单底部才能保存或取消。
- 空状态视觉焦点居中，只有一个明确的新建主操作。
- 当前主机、连接中主机和普通主机状态具有清晰差异。
- 深色主题下边框、背景、按钮、字体和图标与现有设计一致。
- 窄窗口下自动切换单栏，所有文本和按钮不溢出、不重叠。

### 功能验收

- 搜索可以按主机名称、地址或用户名过滤列表。
- 选择主机后可以正常编辑，取消编辑不会错误修改原配置。
- 新建主机、保存、创建并连接流程正常。
- 密码认证和私钥认证的字段切换、校验和提交行为正常。
- 私钥文件浏览功能正常。
- 连接、编辑、删除和删除确认流程正常。
- 连接中状态下禁用逻辑和关闭行为保持正确。
- 多台主机连续选择和编辑时不会出现数据串用。

### 测试与手工验证

- 补充或更新 `HostPickerModal`、`HostForm` 组件测试。
- 至少覆盖：空状态、单台主机、多台主机、搜索无结果、新建、编辑、认证方式切换和删除确认。
- 执行项目现有类型检查、测试和构建命令。
- 在普通桌面宽度、最小支持宽度和较长主机名/地址下进行截图验收。
- 使用键盘验证搜索、列表选择、表单填写、保存、取消和关闭。
- 验证深色/浅色主题以及 `prefers-reduced-motion` 场景。

## 11. 风险与控制

- **表单数据丢失**：切换列表项或关闭编辑区前明确处理未保存内容，必要时复用确认机制。
- **主从布局过窄**：设置合理的最小宽度和响应式断点，窄窗口自动切换单栏。
- **列表性能**：普通数量直接滚动渲染；只有在实际主机数量较大时再引入虚拟列表，不用分页解决未知问题。
- **业务回归**：仅调整展示结构和局部状态组织，保持 `onCreate`、`onUpdate`、`onRemove`、`onConnect` 调用契约不变。
- **滚动容器嵌套**：列表和表单各自只保留一个主要滚动容器，避免滚轮事件在多层容器之间跳转。
- **国际化溢出**：中英文分别验证标题、按钮、状态和错误文案，长文本允许自然换行。

## 12. 实施顺序

1. 确认当前主机管理组件的状态流转和未保存表单处理策略。
2. 调整弹窗宽高，建立主机列表区和编辑区的主从布局。
3. 将 `HostForm` 改为分组和响应式字段布局，增加固定底部操作栏。
4. 增加列表搜索、紧凑主机条目和选中/连接状态视觉反馈。
5. 完成空状态、窄窗口、主题和无障碍样式。
6. 补充中英文文案及组件测试。
7. 执行类型检查、测试、构建和多尺寸手工验收。

## 13. 非目标

- 不增加分页、页码管理或服务端分页接口。
- 不改变主机配置数据结构、持久化格式和连接协议。
- 不在本次迭代加入主机分组、标签、导入导出或批量编辑。
- 不新增第三方 UI 组件库、图片资源或独立设计系统。
